## 二、色彩与字级

```css
--red    #B2222C   /* 唯一强调色：报头块、编号方块、区块标签、必背句下划线、红线 */
--red-q  #93222A   /* 金句粉条里的文字红，比主色沉一点，压得住粉底 */
--tint   #FAEDED   /* 浅粉底：总论点卡、金句粉条 */
--tint-2 #F0D3D4   /* 描边：适用卡虚线 */
--ink    #0B0B0B   /* 标题 */
--body   #262626   /* 正文 */
--sub    #525252   /* 右栏解析 —— 比正文浅一档，主次就出来了 */
--gray   #8A8A8A   /* 灰括号批注、用法说明 */
--gray-2 #AFAFAF   /* 页脚、右栏右对齐小注 */
--rule   #E3E3E3   /* 分隔线 */
```

**整页只有一个强调色。** 所有层级靠字号、字重、灰度拉开，不靠第二第三种颜色。
这是原稿最值得保留的一条纪律，改稿没有破。

红色只出现在四个地方，且面积递减：报头两个色块 → 9 个段落编号方块 →
区块标签与金句数字 → 细下划线与细线。**不再给关键词胶囊描红边**（原稿是红描边红字，
5 个胶囊红色面积不小），改成 `#FAF3F3` 底 + `#7E2A32` 字 + `#E9CFCF` 边，
保留品牌感但降噪，把红色预算让给真正需要抢眼的地方。

### 字级（全部由 `--fs` 推导，`--fs` 是正文基准字号）

**只留 6 档，相邻两档至少差 12%。** 这是"有层次"的第一条——
之前版本用了 0.82 / 0.78 / 0.76 / 0.74 / 0.72 五档，差 2%—3%，
在 6pt 的字上肉眼根本分不出来，等于没有层级。

| 档 | 倍率 | 用在哪 |
|---|---|---|
| 主标题 | 4.30× | 庞门正道标题体，`line-height:1.02`，`letter-spacing:.005em` |
| 副标题 | 1.22× | 600 字重，`line-height:1.35` |
| **正文** | **1.00×** | `line-height:1.74`，`text-align:justify`，首行缩进 2em |
| 段落标签 | 0.94× | 600 字重（与正文靠字重和编号方块区分，不靠字号） |
| 右栏解析 | 0.84× | `line-height:1.64`，`--sub` 灰 |
| 批注 / 署名 | 0.72× | `--gray` |

CSS 里写成变量，改一处全局生效：

```css
--t-sub:1.22;   /* 副标题 */
--t-lab:0.94;   /* 段落标签 / 区块标题 */
--t-aux:0.84;   /* 右栏解析 / 金句 / 总结 */
--t-note:0.72;  /* 批注 / 署名 / 图例 */
```

### 层次的三个杠杆（按"是否吃版面"排序）

版面只有一页，**加间距 = 缩字号**。所以层次要优先用不吃空间的手段：

| 杠杆 | 吃不吃空间 | 具体做法 |
|---|---|---|
| ① 字号梯度 | 不吃 | 6 档阶梯，拉开到 12% 以上 |
| ② 字重 + 颜色 | 不吃 | 正文 400 `#262626` / 解析 400 `#525252` / 金句 500 `#93222A` / 标签 600 `#111` |
| ③ 区块头差异化 | 不吃 | 左栏「原文」红底白字块（主）；右栏「拆解速览」红竖条 + 红字（辅） |
| ④ 图形锚点 | 不吃 | 段落编号方块 1.32em，是每段的视觉锚；右栏缩到 1.24em 自动降级 |
| ⑤ 间距节奏 | **吃** | 段距 2.7mm、条目距 2.2mm、行高 1.74 —— 已经是这套内容量的上限 |

第 ⑤ 项一旦加过头，字号会被迫缩水。实测：把行高从 1.74 提到 1.80、段距提到 3.2mm 后，
基准字号从 2.23mm 掉到 2.04mm（6.3pt → 5.8pt），**层次有了但字变小了，得不偿失**。
最终取值是在 2.14mm（6.1pt）上找的平衡点。

**实测取值**：第 01 期在 210×315mm 上跑出 `--fs = 2.14mm ≈ 6.1pt`，两栏 98% / 99%。
别嫌小——原稿正文折合 5.7pt，这是"一页塞 1400 字"的格式宿命。
真要更大，只能减字数，不能改倍率（改倍率会把整页节奏打乱）。

## 三、原稿的五个毛病 → 改法

拆稿时逐区放大看过，以下几处不是审美偏好，是**自相矛盾**，所以必须改。

### 1. 右栏第 7 条金句，正文里根本没有
原稿右栏"分论四·底气"配的金句是「改革不是一次性的冲锋，是一套能反复启动的机制。」
——这句话在左侧正文里**一字不见**。正文那段写的是「这种"敢"不是莽，是有兜底的敢——容错机制、试错空间、退出通道，一样都不能少。」

> **改法**：右栏金句一律从左侧下划线句里取。`build.py` 的出厂自检会做子串比对，
> 命不中就报「一致性 · 右栏金句出自原文：未命中 第7条」。
> 这条自检就是为这个坑写的。

### 2. 金句带编号从 3 开始
底部「三句可直接搬进考场」的三条，编号是 **3、4、5**。标题写着"三句"，编号却是 3 起头——大概率是模板里沿用了全局计数器。

> **改法**：`no` 字段由数据给定，自检校验段落 `1..N` 连续；金句带一律 1、2、3。

### 3. 图例承诺了不存在的符号
页脚上方那行写着「笔记符号　— 必背句　● 重点句　● 数据术语　● 考点词　● 分论点　○ 蓝圈」，
六个符号、五种颜色。但整页正文只用了**红下划线**和**加粗**两种，● ○ 一个都没出现。

> **改法**：图例只列页面真用到的标记，且与实际渲染一一对应：
> `红色下划线 = 必背句`｜`加粗 = 论点句`｜`淡红底 = 数据·术语`｜`〔灰括号〕= 段落功能`｜`粉底条 = 可背金句`。
> 图例挪到「句式」栏底部——离它要解释的正文更近，也顺手补掉了那一栏的高度差。

### 4. 金句出现三次，第三次没有新增信息
左栏红下划线 → 右栏粉条 → 底部金句带，同一句话最多出现三遍。原稿底部那三条，
在右栏已经完整出现过，第三次只剩"再抄一遍"。

> **改法**：底部金句带保留（它是"可撕下来背"的功能区），但每条**加一列用法**
> （`use` 字段）：对偶句 → 总论点或分论点首句；反常识 → 分论点开头；收尾句 → 结尾落人。
> 第三次出现必须带来新信息，否则就是占版面。

### 5. 底部两块只占左栏宽，右栏底部空着
「句式」和「金句」两条带子都只铺到左栏宽度（约 63%），右栏从"换题"往下整片留白。

> **改法**：底部改三段式——`句式 ｜ 换题` 并排（都是模板类，本该放一起），`金句` 通栏。
> 右栏因此腾出空间，左栏也不再孤零零地长出一截。

## 四、自动铺满算法

一页纸最怕两件事：**溢出**（字被切掉）和**留白**（半页空着）。手工调字号必然反复。

`build.py` 的做法：

1. 全篇只用 mm，字号一律 `calc(var(--fs) * 倍率)`。
2. 在 `[2.0mm, 4.8mm]` 区间二分 `--fs`，共 16 轮。
3. 每轮量 `#colL .inner` 与 `#colR .inner` 的真实高度，取大者与 `#cols` 可用高度比。
4. 取"刚好放得下"的最大值 → 页面自动填满，且**永远不会溢出**。

两个关键细节（踩过）：

- **不能用 `scrollHeight`**。父元素 `overflow:hidden` 且内容比容器矮时，
  `scrollHeight` 恒等于 `clientHeight`，判定永远"刚好满"，字号会被锁死在最小值。
  必须量子元素 `getBoundingClientRect().height`。
- **左右栏要分别量**。只量高的那栏，另一栏会长期空着一截；两个数都打出来，
  才知道该往哪栏加字。第 01 期实测 98% / 99%，说明右栏已到顶、左栏还差一两行。

输出的 `填充率` 与 `左栏 x% / 右栏 y%` 就是调字数的依据：
两栏都在 95% 以上 → 不用动；某栏低于 85% → 那栏补两三行。

## 五、字体与 PDF 的两个事实

1. **正文别用宋体。** Chromium 下 Songti SC 会出字体映射损坏（乱码 `ÆÓØÜÝâåæìíîô÷üýÿ`）。
   正文一律 `PingFang SC`。

2. **PingFang 导 PDF 会变成 Type3 字形。** Chromium 嵌不进 PingFang（.ttc 合集），
   会把每个字转成 Type3 矢量过程——**打印、放大、检索都不受影响**，代价是
   一页 PDF 约 1.3MB、字体对象三百多个。
   需要"真字体嵌入"的干净 PDF 时，在 content.json 里加 `"font_body": "方正黑体简体"`
   （实测以 Type0 正常嵌入，但字面偏宽、引号形态不同，观感不如 PingFang）。

3. **标题字体**：`庞门正道标题体`（以 Type0 正常嵌入）。缺字时自动回落到
   `Hiragino Sans GB` → `PingFang SC`。可用 `font_head` 换成别的标题体。
